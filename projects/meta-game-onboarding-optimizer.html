Meta Game Onboarding Optimizer: closed-loop onboarding playtests with Meta Muse

A Meta Global AI Developer Hackathon project (indie developer track, theme Build for Your World, Oct 26–Nov 4, 2026, Cerebral Valley): Muse agents play a free-to-play browser game, find where new players get stuck, propose a fix, and verify it only after a human approves. I submitted this project for the event; winners are announced on 9 November 2026.

MuseSAM 3.1Multi-agentPlaytesting

The game under test is Hearths of the Glen, an original Celtic dawn-age village builder built for this project so every fix can be played, not only described.

The problem

The first minutes of a free-to-play game decide whether a player stays. Finding onboarding friction with human playtests and funnel analysis is slow and expensive, and every fix needs another round of testing. I wanted a loop that playtests, diagnoses, proposes a change, waits for a human, and checks whether the change helped.

Approach

Playtester agents use Muse Spark as a computer-use brain. They look at the screen, click through onboarding, and keep a short working-memory scratchpad. Five literature-grounded personas cover different player types (Rush-Clicker, Story-Guided, Strategist, Tinkerer and Hoarder).

The analyst uses SAM 3.1 to mark UI elements in gameplay screenshots and Muse Spark to reason over the session. It builds an onboarding funnel and ranks friction points with linked evidence, including a distractor-to-goal visual salience note from the SAM masks.

The designer proposes a concrete onboarding config patch, or turns a free-text feature idea into a schema-validated feature plugin (Feature Forge), with an emblem from Muse Image or a procedural stub. No patch is applied or playtested until a human approves it.

The experiment agent then reruns the playtesters on the baseline and the patched config as a paired comparison and writes a short Council Report with a clear verdict and side-by-side replay. Bug hunting produces a diagnosis for one run; Feature Forge produces a verdict for one frozen experiment. Those two paths stay separate on purpose.

Limits

Agent playtests are a smoke test, not a sample of real players. Persona findings are hypotheses to check with people. SAM 3.1 marks detected regions; it does not prove what a human would notice. Bot think-aloud is recorded commentary, not a window into hidden model motives. Runtime changes are schema-validated JSON patches only, and every patch stops at the human approval gate. The public demo on Hugging Face uses demo mode without live Meta calls.
